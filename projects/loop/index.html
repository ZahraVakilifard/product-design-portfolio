THE CASE STUDY / SELF-INITIATED CONCEPT

Make the value of loyalty instantly understandable.

Below is the design rationale for the working prototype above. This is a proposed solution, not a commissioned project or a validated user-research outcome.

AUDIENCE

Returning shoppers who have earned points but may be uncertain about redemption conditions.

DESIGN GOAL

Discover available rewards, compare their value, redeem one, and understand the updated order total.

CONSTRAINTS

Different point thresholds, reward eligibility, shipping rules, mobile screen size, and the need for honest confirmation.

01 / THE CHALLENGE

What needs to change?

Points are easy to accumulate but hard to interpret. A customer deciding whether to redeem needs to know what a reward is worth, whether they qualify, and what the final total will be.

02 / DESIGN PRINCIPLES

Rules for the experience.

01

Show the real value

Translate abstract points into concrete savings.

02

Prevent surprises

Display balance changes and checkout impact before commitment.

03

Make recovery easy

Let shoppers change the selected reward before confirmation.

03 / INFORMATION ARCHITECTURE

One connected journey.

  1. 01See balance
  2. 02Browse rewards
  3. 03Choose eligible perk
  4. 04Review checkout
  5. 05Confirm example order

Conceptual task flow, represented by the interactive prototype above. No participant testing has been conducted.

04 / DESIGN EXPLORATION

Choices and trade-offs.

DECISION 01

Balance as hero

A prominent points balance makes progress tangible before a shopper starts comparing offers.

Trade-off: Risk: balance alone can overemphasize accumulation; pair it with redeemable value.

DECISION 02

Disabled high-cost reward

Unavailable rewards stay visible so shoppers understand what they can work toward.

Trade-off: Risk: disabled controls need clear explanatory text, not color alone.

DECISION 03

Explicit checkout review

Savings and remaining points appear before confirmation rather than after.

Trade-off: Risk: tax and shipping edge cases would require real checkout integration.

05 / DESIGN ITERATION

From hidden promo codes to live point math.

V1 / INITIAL WIREFRAME

Coupon Code Copy-Paste

Initial mobile flows generated a voucher string that users had to remember and paste at checkout, creating drop-off and balance confusion.

V2 / FINAL SOLUTION

Inline Balance Preview

Integrated reward selection directly with checkout math, displaying remaining points and dollar savings in real time before final confirmation.

07 / STATES & EDGE CASES

Beyond the happy path.

  • Not enough points
  • Reward selected / not selected
  • Reward applied
  • Example order confirmed
08 / VALIDATION PLAN

What we would test next.

  • Can shoppers tell which reward is affordable?
  • Can they predict their remaining points before redeeming?
  • Can they change their minds without losing their place?

Success signals to measure: Reward comprehension, checkout-total accuracy, completion and recovery rates.

These are proposed evaluation criteria. No participant interviews, test results, conversion lift, or client impact are represented as completed work.

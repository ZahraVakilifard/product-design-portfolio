THE CASE STUDY / SELF-INITIATED CONCEPT

Replace configuration anxiety with visible confidence.

Below is the design rationale for the working prototype above. This is a proposed solution, not a commissioned project or a validated user-research outcome.

AUDIENCE

Small e-commerce merchants creating their first rewards program without specialist implementation support.

DESIGN GOAL

Choose a program objective, configure valid reward rules, inspect the shopper preview, and activate a local demo.

CONSTRAINTS

Rule dependencies, incomplete merchant information, accessibility of the preview, and the difference between draft and published state.

01 / THE CHALLENGE

What needs to change?

Merchants setting up a loyalty program face a dense set of rules with unclear customer-facing consequences. The design challenge is making configuration understandable before anything goes live.

02 / DESIGN PRINCIPLES

Rules for the experience.

01

One decision at a time

Use a guided flow rather than an unstructured settings page.

02

Preview the consequence

Pair editable rules with the customer-facing representation.

03

Validate early

Explain conflicting values before allowing activation.

03 / INFORMATION ARCHITECTURE

One connected journey.

  1. 01Choose objective
  2. 02Configure rules
  3. 03Inspect preview
  4. 04Validate setup
  5. 05Activate local demo

Conceptual task flow, represented by the interactive prototype above. No participant testing has been conducted.

04 / DESIGN EXPLORATION

Choices and trade-offs.

DECISION 01

Goal-led onboarding

A business objective creates context for later rule choices.

Trade-off: Risk: different objectives need tailored defaults and explanation.

DECISION 02

Side-by-side preview

A live customer card turns abstract settings into something inspectable.

Trade-off: Risk: preview is representative, not a complete storefront integration.

DECISION 03

Guardrails on amounts

Simple numeric constraints prevent contradictory reward settings.

Trade-off: Risk: a production rules engine would need many more validations.

06 / STATES & EDGE CASES

Beyond the happy path.

  • Empty program name
  • Reward exceeds minimum order
  • Valid draft
  • Active local demo
07 / VALIDATION PLAN

What we would test next.

  • Can merchants configure a valid program without outside help?
  • Do they notice and understand invalid reward combinations?
  • Can they explain what a shopper would actually see?

Success signals to measure: Time to valid setup, configuration errors, preview comprehension, activation confidence.

These are proposed evaluation criteria. No participant interviews, test results, conversion lift, or client impact are represented as completed work.
